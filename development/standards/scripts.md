## Central distro

> Source: `development/wiki/archive/old/root/backend.md#11--central-distro` (archived 2026-11-21).

Central is the network home: **FastAPI + Turso** on Railway, served through the
GitHub Pages proxy at `flove.org/api/*`. Apps stay single-file; the **Browsy**
extension carries identity (Ed25519, email + Telegram), trust (3-hop web of
trust) and sync (batched, IndexedDB queue).

| Property | Value |
|---|---|
| Backend | FastAPI + Turso (libSQL), serverless on Railway |
| Serving | GitHub Pages with an API proxy |
| Apps | single-file HTML, self-contained, no build step |
| Identity | Browsy (Ed25519, email + Telegram) |
| Trust | 3-hop web of trust, CRDT vector clocks |
| Sync | batched 5 min, offline queue in IndexedDB |

The extension does the heavy lifting; apps are thin presentation layers. The
full plan — API contract, extension bridge, app structure, navigation, auth,
persistence and sync — lives in the archived `plans/central-backend.md`.
Publishing is `frontend/publish.md`; per-page adoption is `experience.md`.

## Distro adoption (§13.11)

> Source: `development/wiki/archive/old/root/adoption.md#distro-adoption-1311--self-contained-trunk` (archived 2026-11-21).

**The enrichment loader is retired from this trunk (2026-11-15).** There is no
tier-gated `flove-loader.js` rollout: the mini → super variants survive only as
demo sketches under `apps/blogy/`, `apps/economy/dealy/`, `apps/puzzy/keys/` and
`apps/appy/`.

| Layer | Where it lives | Loaded at runtime |
|---|---|---|
| `floveStore` / `floveFields` / `flovePort` | inline block in each app | always (inline) |
| `flove.js` | inline where used (Fivy, Blogy) | inline |
| `flove-appy.js` | inline where used (Goddy, Souls, PracSys, MyFamily, Inventary, Realy) | inline |
| `flove-theme.js` + `flove.css` | inline where used (Puzzy launcher) | inline |
| `vendor/leaflet/leaflet.{css,js}` | `apps/economy/dealy/vendor/` | local files (Freed only) |
| webfonts (Inter + display face) | inline `@font-face` + `data:` URI in every page | always inline |
| FontAwesome (subset) | inline `@font-face` + only that app's icons | always inline |

`addons/code/{css,js}` is the reference set: it documents the canonical shape,
ships in the offline package, and is never referenced by an app's markup. No app
links a stylesheet (only favicons and Freed's local Leaflet); fonts and icons are
inline `data:` URIs.

## Distro pipeline

> Source: `development/wiki/archive/old/apps/README.md#pipeline` (archived 2026-11-21).

1. **Build** — `tools/build-flove-zip.sh` builds `flove-localhost.zip` as a
   path-preserving subset of the repo root; only at `updaty4`, on request.
2. **Service worker** — `sw.js` at root is generated by
   `node tools/build-sw.mjs`; only in the heavy `updaty4` release.
3. **Download** — the zip ships from flove.org as
   `tools/flove-localhost.zip` and is attached to GitHub Releases.
4. **Android TWA** — `tools/flove-apk/` builds the APK/AAB that wraps flove.org;
   rebuilt only when manifest settings change. The signing key stays in
   `tools/flove-apk/android.keystore` — never committed.
5. **Routing.json** — `tools/routing.json` (`flove-routing/3`,
   `version: FloveRouting26-11`); each app carries `flove-fields/1`;
   `tools/extract-fields.py --apply` reproduces `apps[].fields`, `fieldCount`
   and `status` from it. App tiers are absent on purpose.

## Enforcement

> Source: `development/wiki/archive/old/apps/README.md#enforcement` (archived 2026-11-21).

`tools/dev/check-distro.sh` is the single distro gate. It checks the
entry pages, the single canonical `development/addons/media/` folder, that no
`apps/shared` code tree exists, that no internal link is root-absolute, that
every local `href`/`src` resolves, the app routing count, and whether `sw.js`
matches the tracked tree. Run it before publishing; `--build` also rebuilds the
zip to prove packaging.
